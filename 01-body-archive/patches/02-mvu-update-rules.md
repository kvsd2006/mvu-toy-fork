# 卡内补丁 #2：`[mvu_update]变量更新规则` 追加段

## 位置

角色卡世界书条目 `[mvu_update]变量更新规则` 的**末尾**追加 1 小节，并在 `主角:` 类型块内补一段节点声明（见 #2b）。

## 锚点稳定性

这个条目是协议层描述但迭代并不慢（V3.5.1 → V3.5.6 就有 4 处改动）。末尾追加不修改原文任何一行，因此始终可用；
实测 V3.5.6 条目以 `if (!isCombat) { 传闻… }` + `<%_ } _%>` 收尾，追加内容位于 EJS 之外，任何状态下都会下发。

## 补丁全文

```markdown
### 动态肉体档案维护规则（专用）

**用途定位**：`主角.动态肉体档案` 是**纯外观 + NSFW 语义**的快速参考，**不参与任何战斗/属性/EP/HP 计算**。作用是让 AI 一眼看到主角当前的肉体状态、穿着、配饰、性器状态，用于：
- 在剧情里准确描写主角的样子（基于档案填表，不要凭空想象）
- 在 NSFW 场景里合理利用现有配饰（如跳蛋、贞操带、颈圈等）和当前性器状态
- 让身体反应（兴奋度、敏感、伤痕）具有跨回合连续性

**字段结构**：
- `肉体外观`：`身高·体重`（如 160cm/45kg）、`三围·罩杯`（如 96/52/88 G）、`外貌`（短语概括）
- `衣物服饰`：`上装`、`下装`、`内衣`、`内裤`、`袜子`、`鞋履`、`包袋`
- `情趣配饰`（解剖学 key，17 个）：`身体`、`头部`、`耳部`、`口部`、`颈部`、`胸部`、`腰部`、`腹部`、`臀部`、`手部`、`腿部`、`脚部`、`外阴`、`阴道`、`子宫`、`肛部`、`尿道`
- `性器状态`（解剖学 key 的子集，8 个核心性部位）：`口部`、`胸部`、`外阴`、`阴道`、`子宫`、`肛部`、`尿道`、`臀部`
  两个档案共用同一套 key 命名。情色风味写入 value（如 `外阴: "牝户充血、阴蒂敏感"`），key 保持中性。
  手脚、颈部等非核心部位在正文中描述即可，不纳入档案追踪。

**填表风格约束**：
- 每个字段值用**短语或关键词**，禁止整段描述
  - ✓ `"黑色蕾丝胸罩"`  ✗ `"她穿着一件精美的黑色蕾丝胸罩..."`
- 字段不再适用时用 `remove` 删，不要写"无"或"暂无"

**性器状态描写风格（三语气模式）**：

AI 根据剧情上下文自动判断语气，不引入额外变量：

| 模式 | 触发 | 标准 |
|------|------|------|
| 冷静 | 无性暗示 | 中性简练，仅陈述必要状态 |
| 煽情 | 桃色/发情氛围但未性交 | 香艳优雅，半遮半掩 |
| 淫靡 | 至少一方性器官直接参与 | 直白高密度，每值必备器官名+修饰+体液/反应 |

**冷静**
  ✓ `"闭合"` `"正常"`
  ✗ 使用煽情/淫靡词汇

**煽情** — 粗直词→优雅词的映射示范（AI 据此类推其余部位）：
  外阴→花户/幽谷  阴道→花径/蜜道  胸部→酥胸/玉乳
  湿润→濡湿/泛潮/微润  敏感→轻颤/酥麻
  ✓ `外阴:"花户微润，阴核轻颤"`  ✗ `外阴:"湿了"`

**淫靡** — 每值同时包含三项信息：
  ① 器官名  ② 至少一个色情修饰词（充血/痉挛/湿糯/嫩红/合不拢…）
  ③ 体液/身体反应（淌下/挤出/绞紧/灌满/外翻…）
  ✓ `外阴:"湿糯的花唇充血外翻，淫水顺着股缝淌下"`
  ✓ `阴道:"嫩红穴肉痉挛绞紧，抽插间挤出白浊泡沫"`
  ✗ `"很湿""被插了""不行了"`（缺器官名/空泛）

**维护时机**（必须触发 mvu_update）：
1. **剧情变化**：穿脱衣物、TF/性别变化、伤痕、佩戴/取下配饰、性器状态变化（兴奋/高潮/疲倦）
2. **OOC/元指令**：玩家用括号或 OOC 明确要求更新
3. **NSFW 场景开始与中段**：进入性场景时主动同步性器状态、敏感部位、配饰使用情况

**更新方式**：
- replace 的 path 必须精确到叶子槽位，value 为字符串：
  `replace /主角/动态肉体档案/<子档案>/<槽位> "<值>"`
- 禁止 replace 整个子档案对象（JSON Patch 是整值替换，会清空同子档案下的其他槽位）
- `remove /主角/动态肉体档案/<子档案>/<槽位>` — 删除不再需要的槽位

**槽位自由扩展**：四个 record 内部字段不固定。AI 可根据剧情需要新增 key，key 名简洁、与现有风格一致。

**配饰-状态联动**：情趣配饰与性器状态共用解剖学 key，同 key 必须成对维护：
- 更新情趣配饰 `外阴` → 同步更新性器状态 `外阴`
- 更新性器状态 `肛部` → 检查情趣配饰 `肛部` 是否也应同步

**⚡优先级提醒**：剧情涉及肉体/衣物/配饰/性器变化时，本档案的 mvu_update 与其他系统（HP/状态/装备）同等优先级，**不可遗漏**。
```

## 补丁 #2b：`主角:` 类型块内声明档案节点（V3.5.6 起建议加）

### 为什么要加

V3.5.6 收紧了 schema 纪律：

- `[mvu_update]变量更新规则` 的 `全局.新节点硬约束` 要求「insert 必须覆盖目标节点 type 定义的全部字段」；
- `全局.新节点硬约束 / insert非空约束 / 新物品路由与格式铁律` 都指向「以 type 定义为准」。

档案节点此前只靠「补丁 #2 的维护规则小节」描述；再加上类型声明后，AI 在 `主角` 下就有了该节点的类型依据，
与 ZOD schema（补丁 #1）一致，避免 AI 认为 `动态肉体档案` 是未定义字段而不敢写。

### 锚点

`主角:` 类型块内 `当前形态: &current_form` 子块的最后一个 check 行之后（其后原文为空行 + `  资产:`）：

```
          - 激活时判定/承伤直接作用于本体HP/EP；单次极高伤害时视情况将形态标记破损并强制解除

  资产:
```
