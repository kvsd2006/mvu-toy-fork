# 01 - 动态肉体档案

> 在悬浮球「信息」页面追加「动态肉体档案」，集中追踪主角的**肉体外观 / 衣物服饰 / 情趣配饰 / 性器状态**。
>
> 纯外观展示，**不参与战斗/属性/EP/HP 计算**；同时作为 NSFW 场景的快速语义参考。

## 设计要点

| 维度 | 选择 |
|---|---|
| 数据流方向 | AI 双向（既写也读） |
| 字段结构 | `角色.动态肉体档案.{肉体外观,衣物服饰,情趣配饰,性器状态}` 各 `record<string,string>` |
| 填表风格 | 短语 / 关键词，不写整段描述 |
| 维护时机 | 剧情变化 / OOC 元指令 / NSFW 场景进入 |
| 改动原则 | 最小补丁 + 外部 fork |

> **⚠️ 根节点改名（V3.6.11 起）**：变量根节点由 **`主角` → `角色`**。世界书 / ZOD schema / `[variables]当前变量` EJS / 悬浮球 JS 全部同步改名。
> 本目录的补丁文本、dist 都已按 `角色` 更新；若是给 V3.5.x 及更早的卡打补丁，把 `角色` 读回 `主角`。

## 部署步骤

> V3.6.11 起角色卡的 `悬浮球状态栏` 脚本已经是 `import '<上游 CDN>/V20260917/悬浮球状态栏.js?v=2'` 的形式，**只需把这个 URL 换成 fork 的 dist**（不必再取卡内联脚本）。

1. **应用卡内补丁**：按 `patches/01-zod-schema.md`、`patches/02-mvu-update-rules.md`（含 #2b）、`patches/03-current-variables-ejs.md` 的说明，把 3 处补丁粘到角色卡对应位置
2. **改 import URL**：找到角色卡 `extensions.tavern_helper.scripts[]` 里 `name: "悬浮球状态栏"` 的脚本，把 `content` 改为：
   ```
   import 'https://testingcf.jsdelivr.net/gh/kvsd2006/mvu-toy-fork@main/01-body-archive/dist/V20260917/suspension-ball.js?v=2'
   ```
   （其余 `辅助计算脚本` / `世界推进系统` / `MVU脚本` 仍指向上游，不要动）
3. **验证**：在 SillyTavern 加载角色卡 → 悬浮球 → 信息 Tab → 看到「动态肉体档案」区块（首次为空，编辑模式下手动加槽位，或剧情推进后 AI 自动填入）

> 备选（不想依赖 CDN / 无法 push 时）：把 `悬浮球状态栏` 脚本 content 直接替换为 `dist/V20260917/suspension-ball.js` 的全文（内联部署）。
> 本目录已按两种方式各生成成品卡（见根目录 `轮回战场 重构版 V3.6.11 - 动态肉体档案*.json` 与 **原版** `轮回战场 重构版 V3.6.11_origin - 动态肉体档案*.json`）。
>
> **魔改版 vs 原版**：两者 ZOD / 变量更新规则 / 当前变量 / 悬浮球 import **逐字相同**，补丁与 dist 通用；
> 唯一差异是**魔改版** `[mvu_update]变量输出规则` 多一条"patch path 必须以 7 个根开头"的白名单（原版无此条，与 V3.5.6 一致）。详见 `../../docs/2026-09-23-V3.6.11变化与动态肉体档案兼容性核验.md` §2.5。

## 升级工作流

| 场景 | 操作 |
|---|---|
| 改 UI 渲染 | 改 `dist/V20260917/suspension-ball.js` → commit → push → 卡内 `?v=N` 递增 |
| 原作者发新悬浮球 JS | 拉上游新代码 → 按 `patches/04` 的「重建步骤」插入两段 → push → `?v=N` 递增 |
| 原作者发新卡 | 先确认卡是 import 型还是内联型（决定基底）→ 重建 dist → 重贴卡内补丁（位置锚点见 `patches/`）→ 卡内 import 指向新 dist |

详细见 [`docs/复用迁移手册.md`](./docs/复用迁移手册.md)（已按 V3.5.1 → V3.5.6 → V3.6.11 迁移实录编写）。

## 与其他子系统的边界

| 子系统 | 关系 |
|---|---|
| `辅助计算脚本` | 只写 `角色.最终属性` 等数值，不碰档案 |
| `世界推进系统`（V3.6.11 新增） | 只维护 `世界.*`（后台/时间/事件/场外场景等），**不写 `角色` 子树**；实测源码无 `角色.形态库/状态/道具` 等写入 |
| `关系列表` NPC 的 `外貌` / `着装` | 是 NPC 专属的 ≥30 字**散文**字段，与档案（主角、短语、结构化）语义不重叠，互不干扰 |
