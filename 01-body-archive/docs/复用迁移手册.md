# 动态肉体档案 — 复用迁移手册

> 适用场景：原作者发布新卡 / 新悬浮球 JS 后，把「动态肉体档案」补丁迁移到新版本。
>
> 本文按 2026-09-11 的 **V3.5.1 → V3.5.6 迁移实录** 编写，步骤可直接复用。

---

## 0. 迁移前检查（三处锚点必须先在，才开工）

用 `tmp/check_anchors_v356.py` 同款脚本核验新卡：

| 检查项 | 期望 |
|---|---|
| ZOD 脚本内 `主角: z.object({` 存在，且该块内有 `空间币`、`形态库: z.record(z.string(), form_item).prefault({}),`、`当前形态: current_form` | 各 1 次 |
| `npc_schema` 内**不含** `动态肉体档案` | 补丁不能打到 NPC schema |
| `[mvu_update]变量更新规则` 内有 `主角:` 块、块尾 `当前形态` 的 check 行、随后 `  资产:` | 1 次 |
| `[variables]当前变量` 内有 `  EP: data.主角.EP\n};` | 1 次 |
| 卡内联 `悬浮球状态栏` 内有 `// ★ 选择世界按钮(顶栏, …)`、`// 注: "当前形态"栏已移除 …` | 各 1 次 |

任一项不满足 → 先停下来改锚点，不要硬改。

## 1. 重建 fork dist（卡外补丁）

**关键原则：基底取「新卡内联脚本」，不取上游原版。**

作者常在内联脚本上做本地修正（V3.5.6 就有 `心里话`→`态度`、资产类型图标兼容、商城提示词档位等约 290 字符差异）。
用上游原版会把这些修正丢掉。

```
1) 读新卡 JSON → data.extensions.tavern_helper.scripts[] 里 name=="悬浮球状态栏" 的 content  = 基底
2) 断言两个锚点各 1 次（见 §0）
3) 插入两段补丁：
     ①「添加槽位」事件绑定 → 插在 `// ★ 选择世界按钮…` 那一行之前
     ② 信息页 4 个 secBlock → 插在 `renderInfoTab` 内、`return html;` 之前
4) 写入 01-body-archive/dist/<上游版本号>/suspension-ball.js
5) 校验：与基底 diff 必须恰好是 2 段 insert；`node --check` 通过
```

参考实现：`tmp/build_fork_v20260901.py`（从上一版 fork dist 里提取两段 hunk，避免手工转录出错）。

## 3. 部署方式二选一

| 方式 | 做法 | 适用 |
|---|---|---|
| A. CDN import | `悬浮球状态栏` 脚本 content 改为 `import '<jsdelivr>/01-body-archive/dist/<版本>/suspension-ball.js?v=N'` | 仓库已 push；后续改 UI 不必重做卡 |
| B. 内联 | 直接把 dist 全文写进 `悬浮球状态栏` 脚本 content | 无法 push / 想离线自洽；卡体变大（约 +0.6 MB） |

两种方式本次各出一份成品卡，见工作区根目录：

- `轮回战场 重构版 V3.5.6 - 动态肉体档案.json`（内联，1,466,303 B）

### 踩坑记录

1. **jsdelivr 的版本列表 API 会严重缓存过期**：`data.jsdelivr.com/v1/packages/gh/<user>/<repo>` 当时只列到 V20260809，
   实际 `@main` 已有 V20260901。核对上游版本请看 `https://<cdn>/gh/<user>/<repo>@main/dist/` 目录页或直链响应。
2. **GitHub 直连在本机不可用**（`git ls-remote` / HTTPS 均被 reset），只能用 jsdelivr 取上游文件。
   因此 fork 的 push 需在有网环境执行；push 前不建议在卡内启用 CDN import（会 404 导致 UI 完全不加载）。
3. **卡内 YAML 锚点缩进敏感**：`当前形态` 子块内的 check 行是 **10 空格**（`          - 激活时判定/…`），
   `主角:` 下的字段是 **4 空格**，写补丁时先 `repr()` 出原文再拼。
4. **PowerShell 内联 python 引号易炸**：含中文与引号的脚本一律落盘成 `.py` 再跑（本项目 `tmp/` 下已有多个可复用脚本）。
5. **卡内 JSON 输出格式**沿用既有习惯：`json.dump(..., ensure_ascii=False, indent=4)`。
