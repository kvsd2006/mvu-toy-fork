# 动态肉体档案 — 复用迁移手册

> 适用场景：原作者发布新卡 / 新悬浮球 JS 后，把「动态肉体档案」补丁迁移到新版本。
>
> 本文按 **V3.5.1 → V3.5.6 → V3.6.11** 两次迁移实录编写，步骤可直接复用。

---

## 0. 迁移前检查（锚点必须先在，才开工）

用 `tmp/check_anchors_v356.py` / `tmp/analyze_v3611.py` 同款脚本核验新卡：

| 检查项 | 期望 |
|---|---|
| ZOD 脚本内**主 Schema** 有 `角色: z.object({`（V3.5.x 及更早为 `主角: z.object({`），且该块内有 `空间币`、`形态库: z.record(z.string(), form_item).prefault({}),`、`当前形态: current_form` | 各 1 次 |
| `npc_schema` 内**不含** `动态肉体档案` | 补丁不能打到 NPC schema |
| `[mvu_update]变量更新规则` 内有 `角色:` 块、块尾 `当前形态` 的 check 行、随后 `  资产:` | 各 1 次 |
| `[variables]当前变量` 内有 `  EP: data.角色.EP\n};` | 1 次 |
| `悬浮球状态栏`（上游版本或卡内联）内有 `// ★ 选择世界按钮(顶栏, …)`、`// 注: "当前形态"栏已移除 …` 且后者紧跟 `return html;` | 各 1 次 |

任一项不满足 → 先停下来改锚点，不要硬改。

**先判断卡是哪种形态**（决定第 1 步基底）：

| 卡形态 | 判据 | 悬浮球基底 |
|---|---|---|
| **内联型**（V3.5.x 及更早） | `悬浮球状态栏` 脚本 content 是一大段 JS（几十万字符） | **卡内联脚本**（含作者本地修正） |
| **import 型**（V3.6.11 起） | content 是一行 `import '<CDN>/…/悬浮球状态栏.js?v=N'` | **上游对应版本原版 JS** |

## 1. 重建 fork dist（卡外补丁）

```
1) 取基底：
     - import 型 → 上游 <CDN>/dist/<版本>/悬浮球状态栏.js
     - 内联型  → 卡 data.extensions.tavern_helper.scripts[] 里 name=="悬浮球状态栏" 的 content
2) 断言两个锚点各 1 次（见 §0），且第二个锚点紧跟 return html;
3) 插入两段补丁：
     ①「添加槽位」事件绑定 → 插在 `// ★ 选择世界按钮…` 那一行之前
     ② 信息页 4 个 secBlock → 插在 `renderInfoTab` 内、`return html;` 之前
     ⚠️ hunk 里的完整点路径前缀要用当前卡的根名（V3.6.11+ = `角色.`，V3.5.x- = `主角.`）
4) 写入 01-body-archive/dist/<上游版本号>/suspension-ball.js（行尾沿用 CRLF）
5) 校验：与基底 diff 必须恰好是 2 段 insert；`node --check` 通过
```

## 3. 部署方式二选一

| 方式 | 做法 | 适用 |
|---|---|---|
| A. CDN import | `悬浮球状态栏` 脚本 content 改为 `import '<jsdelivr>/01-body-archive/dist/<版本>/suspension-ball.js?v=N'` | 仓库已 push；后续改 UI 不必重做卡 |
| B. 内联 | 直接把 dist 全文写进 `悬浮球状态栏` 脚本 content | 无法 push / 想离线自洽；卡体变大（约 +0.65 MB） |

本次对 **魔改版** 与 **原版 `_origin`** 各出两种方式，共 4 份成品卡，见工作区根目录：

- 魔改版：`轮回战场 重构版 V3.6.11 - 动态肉体档案.json`（内联）/ `… (CDN版).json`
- 原版：`轮回战场 重构版 V3.6.11_origin - 动态肉体档案.json`（内联）/ `… (CDN版).json`

> 两版的三处卡内锚点逐字相同（ZOD 脚本 sha256 也相同），补丁可直接套用；差异只有魔改版 `[mvu_update]变量输出规则` 里那条根路径白名单。

### 踩坑记录

1. **变量根节点改名是本次唯一的实质风险**：`主角`→`角色` 同时出现在 ZOD schema、世界书 `[InitVar]/[variables]/[mvu_update]` 与悬浮球 JS 里。
   旧补丁的 4 个锚点里有 3 个是"块名/字段名"锚点，全部命中失败或打错位置 → 必须逐条按新名重新定位。
   **特别**：`format` 型 YAML 块里的 `形态库: &form` 的 `path:` 也改成了 `/角色/形态库/${形态名}`，但 `&current_form` 锚点行原文未变。
2. **新卡没有内联悬浮球了**：直接用上游 V20260917 原版做基底。V3.5.6 时代的作者本地修正（`心里话`→`态度` 等）实测已合入上游 V20260917（`心里话` 0 次 / `态度` 12 次）。
3. **魔改版 `[mvu_update]变量输出规则` 新增了根路径白名单**（`/世界 /角色 /任务 /关系列表 /资产 /系统状态 /传闻`）。
   但要注意：**这条只在魔改版有**，同版本的原版 `_origin` 该条目与 V3.5.6 逐字相同（2,038 字符 / sha `ede4f597…`），没有任何路径限制。
   改名之所以必需，依据是 **ZOD schema 与变量树根节点本身都是 `角色`**（两版一致），而不是这条白名单 —— 在**没有**白名单的原版上，AI 写错根只会被 ZOD 静默丢弃，反而更依赖补丁 #2b / #3 做路径锚定。
4. **jsdelivr 的版本列表 API 会严重缓存过期**：核对上游版本请看 `https://<cdn>/gh/<user>/<repo>@main/dist/` 目录页或直链响应。当前最新 = `V20260917`。
5. **GitHub 直连在本机不可用**（HTTPS 被 reset），只能用 jsdelivr 取上游文件。因此 fork 的 push 需在有网环境执行；
   push 前不建议在卡内启用新 CDN import（会 404 导致 UI 完全不加载）。
6. **卡内 YAML 锚点缩进敏感**：`角色:` 为 2 空格，其下字段 4 空格，`当前形态` 子块内的 check 行是 10 空格。写补丁前先 `repr()` 出原文再拼。
7. **PowerShell 内联 python 引号易炸**：含中文与引号的脚本一律落盘成 `.py` 再跑（本项目 `tmp/` 下已有多个可复用脚本）。
8. **卡内 JSON 输出格式**沿用既有习惯：`json.dump(..., ensure_ascii=False, indent=4)`。
